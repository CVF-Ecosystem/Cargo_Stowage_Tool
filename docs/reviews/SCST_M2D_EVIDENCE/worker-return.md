## Decisions per D1–D5

**D1, report model.** One dict, built only from a saved snapshot. The frontend reads it through `/report`, the XLSX writer from the same dict. The shape is in `domain/report/__init__.py` and `api/report_models.py`. Choices where the SPEC left room, each picked to keep data and existing behaviour:

- **Exact values only.**
  - Masses, dimensions and coordinates are ints in g, mm and µm, and the model holds no floats (a test asserts this).
  - `dimensions_um` falls back to mm×1000 for legacy units.
- **Hold status.**
  - With a vessel, it is the profile's `field_status.hold` (VINAFCO: ESTIMATED).
  - Without a vessel (m1/m2a), it is `UNCONFIRMED`, so "Chưa xác minh hình học … chưa xác nhận" still shows.
- **Unplaced reasons.**
  - A saved snapshot does not keep planner reasons, so each unit gets a reason code derived from its stored data: `EXCLUDED`, `REQUIRED_UNPLACED` or `OPTIONAL_UNPLACED`.
  - The optional text states that planner reasons are not saved with the plan.
- **Envelope volume.**
  - An exact integer mm³ only when the µm³ sum divides by 10⁹; otherwise `null`.
  - Always paired with exact decimal text (`*_mm3_text`), so JS never sees an unsafe integer.
- **Notices, in fixed order.**
  - GEOMETRY_UNVERIFIED (hold not MEASURED), SINGLE_LAYER (always), PACKING_DERIVED (pipe list, i.e. units carrying a source group), NEEDS_RECHECK, REVISION_UNAVAILABLE, SOURCE_WARNING (groups with `dimension_warning`), NOT_OPERATIONAL (with the unchecked list).
  - Reviewer-local repair: the first draft keyed PACKING_DERIVED on `kind == PIPE_BUNDLE`, which raised it for the synthetic m1 demo, whose units have no packing. The lead re-keyed it to pipe-list units and updated two test expectations.
- **Recheck.** Uses `plan_binding.recheck` against `plan_binding.latest()`. If the latest revision cannot be served: `REVISION_UNAVAILABLE`, counts 0. A broken **pinned** revision is refused (400) by `bind`.
- **Packing.** Per unit, from `pack_revision` of the pinned revision (v1 is pinned to R0000): the bundle-override packing first, otherwise the group packing.
- **`report_sha256`.**
  - SHA-256 of `json.dumps(sort_keys, ensure_ascii=False, separators=(',',':'))` of the model, without `report_sha256` and `header.generated_utc`.
  - Stable across calls; it changes when the latest revision changes the recheck status.
- **D1.5 `reconcile`.**
  - Checks: placed + unplaced + excluded = total; row counts per status; placed mass = sum of placed units; manifest mass; every total against `evaluate(plan).summary`; the unplaced ids; issues field by field; the hash.
  - A mismatch gives HTTP 500 "Báo cáo không khớp đối soát nội bộ: …; không xuất báo cáo.", and no report is returned.
  - Tested with 12 tampered models plus a 500 through each route.

**D2, API.** `GET /api/snapshots/{id}/report` and `GET /api/snapshots/{id}/report.xlsx`.

- **Read-only.** The only DB access is a SELECT. Tests show the snapshot row and the whole sqlite file are byte-identical after report and XLSX calls, including the real writer at 1076 units.
- **Refusals.** Same as the existing entry points: bad id or data → 400; unknown id → 404; a pinned revision failing integrity or a tampered user-profile sha → 400 through `plan_binding.bind`.
- **Headers.**
  - MIME is `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`.
  - `Content-Disposition: attachment; filename="SCST-bao-cao-<ascii slug>-<id8>.xlsx"; filename*=UTF-8''<percent-encoded "SCST báo cáo <name> <id8>.xlsx">`.

**D3, XLSX.**

- **Parts.** `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml` + rels, `styles.xml` and 4 sheets ("Tổng quan", "Hàng", "Chưa xếp", "Kiểm tra"). Inline strings; no docProps, so no timestamps inside the parts.
- **Header row.** Bold, with a frozen first row.
- **Number cells.**
  - Display cells (kg, cm, m, t) are numeric cells holding the **exact** decimal value, written as text from integer arithmetic, with number formats `0.000` and `0.0###`.
  - The exact µm, mm and g columns are integer cells.
- **Text.**
  - XML is escaped, and illegal control characters become U+FFFD.
  - Vietnamese Unicode is preserved.
- **Deterministic bytes.**
  - Fixed member order, `create_system`, `external_attr` and deflate level.
  - Every zip entry's timestamp comes from the snapshot's `saved_utc`.
  - `generated_utc` is not written, so two downloads are byte-identical.
  - The bytes may differ across zlib versions (Windows and Linux); determinism is asserted within one environment.

**D4, printable page.** `#/report/<id>`, opened from "Xuất báo cáo".

- **Sections:**
  - toolbar: "In / Lưu PDF" (`window.print()`), "Tải XLSX", "Quay lại phương án";
  - header with both hashes;
  - prominent notices box;
  - vessel, hold, limits and cargo cards;
  - totals;
  - SVG 2D plan from the same stored mm positions;
  - one 3D image (see below);
  - units table, all rows, with the header repeated on every printed page;
  - unplaced table;
  - checks.
- **Numbers.** Every number comes from the model. Formatting is exact integer string math, with the exact int beside it. Tonnes alone are rounded to the kg, always beside the exact g.
- **3D image.** Captured from the existing viewer (same plan, packing and profile GLB, angle chosen by the user) through a render-then-`toDataURL` in the same task, with no `preserveDrawingBuffer` change. Auto-captured 2.5 s after mount; "Chụp ảnh 3D" re-captures. Captioned "ảnh minh họa".
- **No WebGL.** The viewer is not mounted and a note explains why; the rest of the page is complete.
- **Print and small screens.** A4 print CSS (12 mm margins, `thead` repeat, `break-inside: avoid` on rows and notices). Usable at 390 px with no page overflow.

**D5.** Nothing out of scope was added: no server-side PDF, no new library, no template, logo, mail or multi-plan report, and no M3.

### M2D-05 browser flow

`tests/browser/m2d.spec.ts` runs this flow:

1. VINAFCO → load pipe list → "Xếp thử tự động" → "Áp dụng xếp thử" → save with a Vietnamese name.
2. Select the plan → "Xuất báo cáo" (new tab). The page is then checked against the JSON model:
   - name and every notice exact;
   - totals exact;
   - all 1076 rows' g and µm and x/y;
   - SVG rect count = placed count, and the first rect at the stored mm position;
   - 3D image present.
3. "Tải XLSX": byte-equal to the API body, and the browser takes the UTF-8 `filename*` name.
4. "In / Lưu PDF" calls `window.print` once.
5. `page.pdf` A4: more than one page. Its text, extracted by a small dependency-free helper in the spec (ToUnicode CMaps), contains the plan name and every notice.
6. A new revision overriding a placed bundle's mass makes the old plan's report show "Cần kiểm lại" / NEEDS_RECHECK with a new hash. The stored plan JSON is unchanged throughout.

Other cases: without WebGL (note shown, no image), 390 px (no page overflow), unknown id (alert).

## Failed attempts and fixes

- **Download name.** The first spec run got `suggestedFilename() == "download"`. The lead reproduced it with a bare server: any non-ASCII `filename*` gave "download" when the container had no locale (`LANG` unset), and the correct UTF-8 name with `LANG=C.UTF-8`. The header was right, so the app was not changed. The two soft "ASCII name" checks were replaced by one hard check that the browser uses the decoded `filename*` name. Running the browser on Linux needs a UTF-8 locale; Windows is unaffected.
- **Shared suite DB.**
  - In the first full run, `pipe-list.spec.ts` (4) and `sup01.spec.ts` (1) failed after `m2d.spec.ts` created a revision. Those specs, which sort after m2d, expect the shared suite DB to still be at R0000 (an existing order dependence; `sup02a` sorts after them).
  - Existing specs and the config were not edited. Instead the M2D-05 flow starts its **own** backend on port 8768 with its own temporary `SCST_DATA_DIR`, using the same command shape as the committed webServer. It uses `..\..\.venv\Scripts\python.exe` on Windows and `python` elsewhere; `SCST_TEST_PYTHON` overrides it.
  - The full suite then passed 50/50.
- **PDF text.** Chromium positions glyphs one by one, inserts private-use code points and leaves some ASCII out of single-byte ToUnicode maps. The helper falls back to ASCII for those codes, and the comparison strips whitespace, soft hyphens and U+E000–U+F8FF on both sides.
- **Print layout.** Units-table cells broke words mid-word (for example "Shee t1-"). The lead fixed this with print-only rules: no mid-word breaks, nowrap ID and group, smaller cells.

  - Report, XLSX and page carry exact integer g, mm and µm beside the practical kg, cm, m and t.
  - XLSX display cells hold the exact decimal, not a rounded value.
  - The page never recomputes report numbers (the browser test matches every unit row and total to the model).
- **DA02: no persistence change.**
  - Exports are read-only (one SELECT). Snapshot rows and the sqlite file are proven byte-identical.

  - Mandatory notices: geometry not verified (with ESTIMATED/SOURCED/UNCONFIRMED wording), single-layer plan, derived packing, recheck needed, source warnings (R022/R031/R032 on VINAFCO), and not operationally eligible.

  - Reused: `evaluate`, `plan_binding.bind`/`recheck`/`latest`/`view`, `vessel_profile_service.detail`, `pack_revision` and the existing Viewer (only optional capture props added).

## Limitations

- The XLSX was **not opened in real Excel or LibreOffice**; it was checked only by stdlib unzip and ElementTree parse. Root checks it on Windows.
- PDFs were produced by headless Chromium on Linux only; Windows printing is not tested.
- The 3D image may be captured before the GLB finishes loading on a slow machine; the user can re-capture.
- Display tonnes are rounded to the kg, always next to the exact g.
- Determinism of XLSX bytes is per zlib build.
- The whole units table prints (about 145 A4 pages for 1076 units).
- On Linux the browser needs a UTF-8 locale for the UTF-8 download name.
- An optional unit's unplaced reason is generic, because planner reasons are not stored.

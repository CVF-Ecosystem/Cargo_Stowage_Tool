# VINAFCO 268 browser proof

Candidate: local BUILD tree, 2026-10-31. Playwright launched the current FastAPI app on loopback `127.0.0.1:8766` and exercised Chromium against real API responses and the served GLB. Command from `apps/frontend`: `.\node_modules\.bin\playwright.cmd test`. Result: **9/9 passed** (four VINAFCO cases and five existing M1 cases, 17.3 s). After adding the geometry receipt, the focused VINAFCO rerun passed **4/4** (11.6 s). No provider API was called and no CVF governance behavior is claimed.

The loaded binary began with the `glTF` header and had 227,984 bytes. The browser's actual Three scene reported 12 cargo meshes and vessel world bounds from `[-39.8725, -0.832, -6.62]` to `[37.9275, 8.568, 6.62]` m after the group translation `[-0.9725, -0.832, 0]` m. The test checks the 77.8 m length, 13.24 m beam, and the full mesh height (including superstructure) against the backend profile; checks every cargo mesh dimension, position and world matrix against the evaluated plan; and records the exact values in [browser-geometry.json](browser-geometry.json). The SI/SII draft markers, camera drag/zoom/reset, cargo picking, and hull hide/show controls were exercised. [Desktop view](browser-vessel-3d.png) and [SI view](browser-vessel-si.png) show the visible result.

The browser checked SI/SII cargo reference ceilings of 3,282.5/3,517.5 t separately from TTTP 3,301/3,536 t; it verified 3,300 t and 3,520 t attempted voyage limits are rejected by the real API with HTTP 422. The profile returned `null` lightship and tanktop load values and an `ESTIMATED` hold. Labels retained the container draft condition and synthetic cargo boundary. A pending edit blocked case switching without losing input; a checked edit survived SI/SII switch and undo. A delayed case response after a newer edit left the prior checked case and newer STALE draft in place.

The first full run exposed an untranslated `Failed to fetch` alert after a simulated case-plan network failure (8/9 passed). The implementation worker localized that failure, and the full rerun passed 9/9. A blocked GLB request left vessel data, cargo editing and validation available in [model failure view](browser-vessel-model-failure.png). Forced WebGL failure on a 390 px viewport showed the accessible 2D map, retained selection and had no page-level horizontal overflow in [mobile fallback view](browser-vessel-mobile-fallback.png). The five original M1 browser cases also passed on the same candidate.

This proof covers the local illustrative viewer and synthetic cargo workflow. It does not establish real hold measurements, stability, strength, operational suitability, owner business acceptance, or any CVF AI governance claim.
